# eww·lint

**Статический анализатор и оптимизатор конфигов [ElKowars Wacky Widgets](https://github.com/elkowar/eww).**
Вставляете `eww.yuck` и `eww.scss` — получаете построчный разбор того, что жжёт CPU, будит shell сотнями fork'ов в минуту и тормозит композитор, с готовыми фиксами для каждой находки.

Всё считается локально в браузере: конфиг никуда не отправляется.

---

## Зачем

Типичный конфиг eww-бара незаметно накапливает нагрузку:

- `defpoll` с интервалом `0.2s` — это **300 запусков shell в минуту** ради цифры громкости;
- `while true; do cat ...; done` в `deflisten` — busy-loop на 100% одного ядра;
- `curl` в опросе каждые 20 секунд — TLS-рукопожатия, батарея, rate-limit;
- `blur(24px)` на пол-экрана — пересчёт фильтра композитором на каждый кадр.

eww·lint находит эти паттерны автоматически, объясняет, почему они дорогие, и отдаёт исправленный фрагмент одной кнопкой. Плюс считает **индекс оптимизации** и **обновления переменных в минуту** — видно эффект от каждого фикса.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # прод-сборка в dist/
npm run typecheck  # проверка типов без сборки
```

Дев-сервер закреплён на порту **3000** (`server.strictPort: true` в `vite.config.js`) — если порт занят, Vite не подберёт соседний, а сразу упадёт с ошибкой.

Стек: React 18 + TypeScript, Vite 6, Tailwind CSS 4. Без бэкенда и внешних API.

## Как пользоваться

1. **Укажите папку конфига** — кнопка **«Папка»** → выбираете `~/.config/eww`, и инструмент сам подтягивает все `.yuck`/`.scss` внутри, определяет корневые `eww.yuck`/`eww.scss` и раскладывает вложенные файлы по include-путям. Альтернатива — **«Импорт»** отдельных файлов или вставка содержимого вручную.
2. **Проверка идёт сама** — анализ перезапускается через секунду после правок; вручную — `Ctrl+Enter` / кнопка «Проверить».
3. **Разберите находки** справа — они отсортированы по серьёзности:
   - **ошибка** — ломает загрузку или гарантированно жжёт ресурсы;
   - **предупреждение** — заметная лишняя нагрузка;
   - **совет** — гигиена и стили.
   Клик по находке переносит к нужной строке в редакторе и подсвечивает её.
4. **Примените фиксы** — у каждой находки есть готовый фрагмент с кнопкой «копировать». Следите, как растут индекс и падает счётчик «обн/мин».
5. **Пример** — кнопка в тулбаре грузит реалистичный бар с набором типичных проблем (~730 обн/мин, ошибки, предупреждения). Удобно, чтобы понять инструмент на чужих граблях.

> Подсказка для копирования из терминала: `cat ~/.config/eww/eww.yuck | wl-copy`

## Вложенные файлы и include

Конфиги обычно разбиты на части: `(include "src/_volumes.yuck")`. Кнопка **«Папка»** подхватывает всю директорию разом: каждый `.yuck` внутри становится отдельной вкладкой с реальным относительным путём, а `eww.yuck` и `eww.scss` определяются автоматически (по имени и глубине). Точечно добавить файл можно кнопками **«+ файл»** (импорт) или **«вставить»** (путь + содержимое) — например, если файл лежит вне выбранной папки. Дальше анализатор сам:

- прогоняет все правила по каждому файлу и помечает находки реальными путями;
- **разрешает include-пути** относительно `~/.config/eww` — точное совпадение → суффикс (`src/_volumes.yuck`) → имя файла (`_volumes.yuck`); неразрешённые помечаются предупреждением прямо на строке include;
- находит **циклы include** (ошибка с распечатанной цепочкой `a → b → a`) и слишком глубокие цепочки (> 5 уровней);
- ловит **дубли определений между файлами** (`defpoll volume` в двух местах) с указанием, где первое;
- помечает подключённые файлы, на которые не ссылается ни один include;
- считает «используется / не используется» для `defvar`/`defwidget` **по всем файлам сразу**.

Подключённые файлы видны чипами в строке `include` под вкладками: клик — открыть в редакторе, `×` — отключить, точка показывает, ссылается ли на файл какой-либо include.

## Правила

Всего **33 правила**: 20 в yuck, 5 в include-графе, 8 в scss.

### Yuck — производительность

| Правило | Серьёзность | Что ловит |
| --- | --- | --- |
| Интервал `defpoll` < 0.3s | ошибка | сотни fork'ов shell в минуту; оправданы только для анимаций |
| Интервал `defpoll` < 1s | предупреждение | вдвое дешевле по CPU при визуально том же результате |
| Часы (`date`) быстрее 1s | предупреждение | секунды — максимум, что видно на экране |
| Громкость поллится | предупреждение | вместо `pamixer` в цикле — `deflisten` на `pactl subscribe` |
| `playerctl metadata` поллится | предупреждение | `playerctl -a metadata -F` стримит изменения сам |
| Батарея поллится | предупреждение | `cat /sys/.../capacity` → `udevadm monitor --subsystem-match=power_supply` |
| Сеть поллится | предупреждение | `iwgetid` в цикле → udev/nmcli-события |
| `curl`/`wget` в опросе | предупреждение | TLS на каждый тик; кэш в файл или интервал в минуты |
| `convert`/`ffmpeg` в опросе < 5s | предупреждение | тяжёлая обработка чаще, чем меняется исходник |

### Yuck — синтаксис и структура

| Правило | Серьёзность | Что ловит |
| --- | --- | --- |
| Несбалансированные скобки | ошибка | eww откажется парсить файл целиком |
| `defpoll` без `:interval` | ошибка | обязательное поле — конфиг не загрузится |
| Неразборчивый интервал | ошибка | поддерживаются только `500ms` / `1s` / `5m` |
| Busy-loop в `deflisten` | ошибка | `while true` без `sleep`/`read` — 100% ядра |
| Два `defpoll` с одной командой | предупреждение | двойной fork; одна переменная на оба виджета |
| `eww update` внутри скрипта | совет | лишний клиент и IPC-раунд — выводите в stdout |
| Инлайн-скрипт > 160 символов | совет | вынести в `~/.config/eww/scripts/*.sh` |
| Неиспользуемые `defvar`/`defwidget` | совет | мёртвый код (проверка по всем файлам проекта) |

### Yuck — разметка окон

| Правило | Серьёзность | Что ловит |
| --- | --- | --- |
| `defwindow` без `:geometry` | предупреждение | окно может растянуться на весь экран — зависит от WM |
| Бар без `:exclusive true` | совет | тайловые окна будут заезжать под бар |

### Include-граф

| Правило | Серьёзность | Что ловит |
| --- | --- | --- |
| Неразрешённый include | предупреждение | путь не найден среди подключённых файлов |
| Цикл include | ошибка | файл включает себя через цепочку |
| Цепочка глубже 5 уровней | совет | уплощите структуру — 2–3 уровня достаточно |
| Файл вне include-графа | совет | подключён к анализу, но ни один include не ссылается |
| Дубль определения между файлами | ошибка | `defpoll`/`defwidget` с одним именем в двух файлах |

### SCSS

| Правило | Серьёзность | Что ловит |
| --- | --- | --- |
| Вложенность селекторов > 4 | совет | длинные селекторы дороже матчить при перерисовке |
| Один hex повторяется ≥ 3 раз | совет | вынести в `$переменную` — смена темы в одну строку |
| `:hover` без `transition` | совет | рывок вместо плавности; 150ms почти бесплатны |
| `box-shadow` с blur ≥ 30px | предупреждение | композитор пересчитывает тень при каждой перерисовке |
| `blur()`/`backdrop-filter` | предупреждение | размытие фона пересчитывается каждый кадр |
| Универсальный селектор `*` | совет | матчится на каждый узел при каждой перерисовке |
| `!important` ≥ 3 раз | совет | борьба со специфичностью — упростите селекторы |
| Большой файл без SCSS-переменных | совет | палитра — в переменные в начало файла |

## Индекс оптимизации

```
штраф = 10 × ошибки + 5 × предупреждения + 2 × советы
индекс = 100 − штраф        (0 находок → 100, минимум — 4)
```

| Индекс | Оценка |
| --- | --- |
| 85–100 | отлично |
| 65–84 | хорошо |
| 40–64 | средне |
| < 40 | требует работы |

**обн/мин** — сумма `60 / интервал` по всем `defpoll`: сколько раз в минуту eww перезапускает shell и перерисовывает зависимые виджеты. У «типичного» бара из примера — около 730; после перехода на событийные `deflisten` остаются единицы.

## Структура проекта

```
src/
├── App.tsx                   # каркас: вкладки, тулбар, импорт, toast, хоткеи
├── components/
│   ├── CodeEditor.tsx        # редактор с подсветкой yuck/scss и номерами строк
│   ├── Diagnostics.tsx       # панель находок: фильтры, метрики, фиксы
│   ├── ScoreDial.tsx         # анимированный индекс оптимизации
│   └── HelpModal.tsx         # инструкция «как пользоваться»
└── lib/
    ├── analyzer.ts           # движок: парсер s-выражений, 33 правила, include-граф
    └── sample.ts             # пример конфига с типичными проблемами
```

Ключевая часть — `analyzer.ts`: собственный парсер s-выражений (строки, бэктики и `;`-комментарии учитываются при балансе скобок), извлечение блоков `defpoll`/`deflisten`/`defvar`/`defwidget`/`defwindow` и построение графа include по всем подключённым файлам.

## Ограничения (честно)

- **Нет фонового доступа к диску** — браузерная песочница не следит за файловой системой: папку с конфигом нужно выбирать явно кнопкой «Папка» (или подключать файлы вручную). Автоперечитывания при правках в редакторе нет — изменения вносите в редакторах инструмента.
- **Правила — эвристики**: они ловят типовые паттерны по тексту, а не измеряют реальный профиль. Экзотические, но честные busy-wait'ы могут остаться незамеченными.
- **Одна SCSS-точка входа**: `@use`/`@import` внутри scss не разворачиваются — вставьте итоговый файл.
- Поддерживается синтаксис **eww ≥ 0.4** (s-выражения). Легаси-конфиги 0.3.x с `<box>`-разметкой не разбираются.
